# a1sheet

An editable React spreadsheet with a formula engine, and Excel/CSV reading and
writing — with **`dependencies: {}`**. No grid library, no parsing library, no
date library. A test enforces that it stays that way.

This Storybook is the documentation. Every claim below has a story you can open
and interact with, and the prop tables are generated from the TypeScript types,
so they cannot drift from the code.

## The five-second version

```tsx
import { Spreadsheet } from "a1sheet/react";

<Spreadsheet defaultWorkbook={wb} />
```

That is the preset. It exists so the first thing you try works. It is **not**
the extension point — see
[Composition over configuration](?path=/docs/start-here-composition-over-configuration--docs).

## Two entry points, permanently

```ts
import { readWorkbookFile, writeXlsx } from "a1sheet";        // no React anywhere
import { Sheet, useSpreadsheet } from "a1sheet/react";        // the only React
```

The root entry point never imports React, so it runs in Node, in a Worker, or in
a plain script. A test enforces the separation.

## What it will not do

Honesty is cheaper than a support thread. The full list with an extension point
for each is in `docs/LIMITATIONS.md`; the ones most likely to matter:

- **Cells do not wrap.** Auto-fitting a row therefore means resetting its height.
- **`.xls` and `.xlsb` are rejected** with an actionable message. Both are binary.
- **Charts, pivot tables, and conditional formatting do not exist.**
- **Committing an edit copies the cell map**, so edit cost grows with the number
  of filled cells — about 26 ms at 10k, about 390 ms at 1M. Rendering does not:
  see [Scale](?path=/docs/scale-large-sheets--docs).
